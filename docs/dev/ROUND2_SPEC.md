# Round 2 build specification

Internal. The scientific design is `docs/design/round-2.md`; read it first. This file fixes what three concurrent work packages build and the contract between them. Where this file is silent, choose the smallest complete solution and record the choice in your notes file. Where it is wrong or contradictory, stop and say so instead of working around it.

## Ground rules

- Round 1 is reproducible from the tag `round-1`. Round 1 code paths that Round 2 does not use may be removed, with one exception: procedural (`reasoning-gym`) families must stay available as evaluation-only sources, because the sealed vault contains twenty of them and the Round 1 selection families serve as a format probe.
- **Blind line.** Nothing may be generated by any model on a blind item, and no blind item may be read into a prompt, before the guard's receipt exists. Loading blind items requires the receipt, as today (`external.items(..., "blind2")`, `blind_suite`). Build-time code may read blind question *texts* for de-duplication only. Round 1's `part_of` assignments for GSM8K test, MATH-500 and MMLU-Pro are frozen; never recompute them differently.
- **Failure principle.** A verifier or loader that cannot decide must raise or mark the item unusable at build time; it must never award credit by default.
- **Shared machine.** Other users run jobs on these GPUs. Never touch processes you did not start. Before using a GPU check `nvidia-smi`; use one with at least 20 GB free and release it when done. Keep CPU pools at 48 workers or fewer.
- **Secrets.** `.env` holds tokens; never print or log them. Sandboxed code must not be able to read `.env`, the repository or home directories.
- **Concurrent commits.** Three developers share one working tree. Touch only files in your package's scope. Commit with an explicit path list (`git add <paths>` then `git commit -m "..." -- <paths>`), never `git add -A` or `git commit -a`; retry if the index is locked. Push after each commit (`git push`). Leave `.mutagenignore` and anything you did not create alone. Run only your own tests while the others are mid-change; the full suite is run at integration.
- Environment: `source scripts/env.sh` in every shell (sets `PYTHONHASHSEED=0`, the Hugging Face cache and endpoint). `math-verify` 0.9.0, `sympy`, `pytest`, `numpy`, `pandas` are installed. New dependencies go in `pyproject.toml`.

## Contract between packages

Field and function names below are binding; everything else is the owner's choice.

```python
# evotaste/tasks.py — owner WP-D
Task(uid, family, domain, kind, question, gold, wrapper, stratum)
#   uid      "<source>/<item id>"
#   family   the source or unit id (name kept from Round 1 to limit churn)
#   domain   "math" | "code" | "logic"
#   kind     "open" | "choice" | "verdict" | "code" | "procedural"
#   question the full user turn, including the answer instruction
#   gold     kind-specific reference
#   wrapper  id of the answer wrapper in force
#   stratum  "mastered" | "sweet" | "frontier" | None

Score(reward, correct_any, complied, channel, truncated, extracted, error)
#   reward       1.0 iff the answer is in the wrapper asked for, verified correct, and the completion stopped
#   correct_any  verified correct under tolerant extraction (any known wrapper); for measuring format loss
#   complied     a final answer was found in the wrapper asked for
#   channel      "direct" | "program" for kind "open", else None

score_many(jobs: list[tuple[Task, str, str]], timeout=None) -> list[Score]     # (task, text, finish_reason)
prompt_ids(tokenizer, question, system=SYSTEM_PROMPT, context=None)            # context: seeding context text for the teacher
Streams.train_batch(step, prompts) -> list[Task]                               # shared by all members of a run
Streams.seed_batch(i, n, domains=None) -> list[Task]                           # prompts for on-policy seeding
fixed_tasks(...)                                                               # probe and evaluation sets, as today

# evotaste/verify/ — owner WP-V
verify_many(jobs: list[Job], timeout=None) -> list[Verdict]     # Job(kind, text, gold, wrapper, channels); Verdict mirrors Score minus truncation
WRAPPERS: dict[str, Wrapper]                                    # id -> instruction text and extractor; TRAIN_WRAPPERS, HELDOUT_WRAPPERS
run_python(code, *, stdin=None, files=None, timeout_s, memory_mb) -> Result    # sandboxed
```

Records keep every `Score` field. The engine (WP-E) treats `Task` and `Score` as opaque except `reward`, `truncated` and what it logs.

## WP-V — verifiers and sandbox

Scope: `evotaste/verify/` (new), its tests, `docs/dev/VERIFY_NOTES.md`.

- **Sandbox.** `bwrap` 0.12 works unprivileged here (about 20 ms overhead). Required: no network, read-only system, tmpfs working directory, address-space and CPU-time limits, wall-clock kill of the whole process group, and the repository and home directories hidden (mount tmpfs over them and bind back read-only only what the interpreter needs: `.venv` and the uv Python under `~/.local/share/uv/python`, to which `.venv/bin/python` is a symlink). A plain `--ro-bind / /` leaves `.env` readable and is not acceptable. Test that a sandboxed program cannot read `.env`, write outside its tmpfs, or open a socket.
- **Wrappers.** The default wrapper is `box` (`\boxed{...}`, last occurrence, balanced braces) for `open`, `choice` and `verdict`, and `code` (last fenced Python block) for `code`. About six training variants and three held-out variants replace `box` in guardrail prompts, for example a last line `Final answer: X`, `<answer>X</answer>`, a last-line JSON object; make them unambiguous to extract and mutually exclusive enough that complying with one is not complying with another. `<answer>` tags must be among the held-out ones (it is the Round 1 format). Extraction for `reward` is strict about the wrapper asked for; `correct_any` tries every wrapper.
- **`open`.** Equivalence through `math-verify` (Round 1's lenient scorer in `evotaste/analysis/format.py` shows working usage), with numeric comparison when either side is a decimal. Answer channels: with wrapper `box` and channels `("direct", "program")`, the final answer is whichever comes last in the response, a boxed expression or a fenced Python block. A program is run (5 s, 512 MB); the last non-empty line of its output is verified like a boxed answer; error, timeout or no output is incorrect with `channel="program"`. With any other wrapper only the direct channel exists.
- **`choice`** — accept, inside the wrapper, the option letter in its usual dressings or the exact option text, resolving to exactly one option. **`verdict`** — a closed label set given by the item.
- **`code`.** Run the item's tests against the extracted program in the sandbox: pytest files that import from `solution` (KodCode), assertion lists (MBPP), `check(candidate)` harnesses (HumanEval+, MBPP+, LeetCode). All tests must pass within the item's time limit.
- **Self-check hooks for WP-D:** `gold_ok(kind, gold)` (the reference verifies against itself; for code, the reference solution passes its tests) so that undecidable items are dropped at build time.
- Tests must include negative cases that Round 1 got wrong in spirit: near-miss numbers, right value in the wrong wrapper, an answer that appears only in the reasoning, a program that prints the right answer among other lines, a hanging or forking program.

**Build rules.**
- Normalise each item to `Task` fields. Drop items whose gold fails `gold_ok`, whose gold is free text (contains `\text`, or longer than 40 characters), or whose prompt exceeds 3,500 tokens.
- De-duplicate question texts across all sources before assigning parts: exact match after normalisation, and near-duplicates by a cheap shingle similarity. Precedence: blind over selection over training; within a part keep one copy.
- Parts. Training sources with an official test split: the test split is held out and halved by text hash between selection and blind. Training sources without one: 5% to selection and 5% to blind by text hash. Unseen units: a seeded draw (seed 20261125) within each domain assigns each unit whole to selection or blind, alternating so the halves are balanced; near-identical units stay together. Write the result to `configs/suites-r2.yaml` with per-part item counts, and never store blind item lists.
- Answer instruction, appended to the question. `open`: boxed, plus the offer of the program channel ("...or end with one Python program in a fenced block whose printed output is the final answer; whichever comes last counts"). `choice` and `verdict`: boxed letter or label. `code`: one fenced Python block defining the named function. A guardrail variant replaces the default instruction by a variant wrapper's instruction and removes the program offer. The system prompt is one fixed sentence asking for step-by-step reasoning and a final answer in exactly the form the problem asks for.
- Training stream. Each batch: domains math 40%, code 25%, logic 35%; equal shares for the sources of a domain; strata 70% sweet, 15% mastered, 15% frontier (fill from sweet when a pool is short); 15% of non-code prompts carry a training-variant wrapper. Deterministic in (run seed, step), without replacement until a pool is exhausted, and shared by all members.
- Probe set from the selection part: about 300 items spread over its units, plus 60 selection items presented with held-out wrappers.

**Census.** A resumable, shardable command that samples the base model through vLLM and scores with `score_many`:
1. training pool, 8 samples per item at temperature 1 with the default instructions, 4,096 tokens (cap sources at about 8k items; all of `math_train` and `kodcode`);
2. selection part, 4 samples per item;
3. on about 1,500 sweet-spot `open` items, 4 samples under each forced channel (instruction offering only that channel);
4. on about 300 probe items, 2 samples under each context of `configs/contexts.yaml` (context appended to the system prompt via `prompt_ids(..., context=...)`).

It writes a strata table (uid, passes, samples) outside git, whose SHA-256 a run config pins and the engine checks, and a summary: per source the pass-rate histogram, strata sizes, response-length percentiles, share truncated, channel shares and per-channel accuracy, wrapper compliance, and per-context accuracy and length. It must refuse blind items by construction.

## WP-E — engine

Scope: `evotaste/trainer.py`, `member.py`, `worker.py`, `sampler.py`, `config.py`, `records.py`, `evaluate.py`, run configs, their tests, `docs/dev/ENGINE_NOTES.md`.

- **Return.** `return = reward − slope · clip((tokens − free) / (cap − free), 0, 1)` with `amplification.length: {free: 2048, slope: 0.25}` and `cap = max_tokens`. This replaces `truncation_penalty`.
- **Advantage.** `amplification.advantage: centered` gives weight `(return − group mean) / 0.5`; groups whose returns are all equal get zero. `standardized` keeps Round 1's rule for comparison.
- **Self-imitation.** `amplification.self_imitation: β` adds `β ×` the token-mean negative log-likelihood of the batch's rollouts with `reward == 1`, normalised by its own token count, to the advantage loss (which keeps its own normalisation). One optimizer step on the sum. `β = 0` is exactly the advantage-only update.
- **Seeding.** `seeding.method: opcd | imitation | none`. For `opcd`: for each of `seeding.steps` updates, the member samples one rollout for each of `seeding.batch` prompts from `Streams.seed_batch(i, n, seeding.domains)` without any context; the loss is the token-mean reverse KL, over completion tokens, from the member's next-token distribution to that of the frozen base model reading the same completion after a prompt that carries the context (`prompt_ids(..., context=text)` with preamble and closing from `configs/contexts.yaml`); one optimizer step; publish; repeat. Log the KL per update. Amplification starts with a fresh optimizer, as today. `imitation` is Round 1's method with the context in the teacher prompt.
- **Clones.** A member spec may name `parent: {member, step}` in the same run. The clone starts from the parent's checkpoint at that step including optimizer state (keep `optimizer.pt` at steps that a spec names as a clone point), takes the parent's step counter, and continues on the shared stream.
- **Sampling seeds.** Every rollout request carries a seed derived from (lineage seed, step, prompt index) so that two clones differ by construction and a rerun is as reproducible as vLLM allows.
- **Limits.** `max_tokens` 4,096 for rollouts, probes and evaluation; check trainer memory with 4k-token sequences and adapt micro-batching. Culling gets `enabled: false`, under which would-be culls are logged and nothing is replaced.
- **Context score.** `python -m evotaste.evaluate context-score runs/<name>`: for each member and probe step, on its stored probe responses, and for each context, the mean over completion tokens of `log p_base(token | context prompt) − log p_base(token | plain prompt)`, by domain; the same for two references generated at prepare time on the probe prompts, the base model's plain responses and its responses under each context. Output is a table; the index is computed in analysis.
- Remove what this makes dead (for example the truncation-penalty path) rather than keeping both.

Defaults for pilot configs: Qwen/Qwen3-1.7B, LoRA as in Round 1, 64 prompts × 4 rollouts, learning rate 1e-4, probes every 15 steps, seeding 40 updates × 64 prompts at 1e-4.

## Integration

When all three packages are in, one toy run exercises the whole path on a GPU: prepare, seed one member by `opcd` and one by `none`, three amplification steps with `self_imitation: 0.5`, a probe, a clone, an evaluation on a few selection units, and `context-score`. The full test suite must pass.
