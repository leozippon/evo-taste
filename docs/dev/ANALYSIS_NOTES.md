# Analysis notes

Internal current-state notes for the pilot analysis in `evotaste/analysis/`: the commands, what they read, every estimator with its validation, the power of the planned pilot sizes, and the limitations. The design questions these numbers decide are in `docs/design/round-2.md` ("What the pilots must show") and, for the amplification pilots D and E, in `docs/design/amplification.md` ("Measurements"); the files are the engine's (`docs/dev/ENGINE_NOTES.md`, "On-disk layout" and "Record schemas"). The commands need no GPU and never load a blind item: evaluations are read from the selection part only. Round 1's analysis is reproducible from the tag `round-1`.

## Commands

Run from the repository root after `source scripts/env.sh`. Each command writes CSV tables and `report.txt` to `results/<run>/<command>/` (`--out` elsewhere) and prints the report.

| Command | Reads | Tables |
|---|---|---|
| `python -m evotaste.analysis.health runs/<name> [--tag T] [--census results/census/<c>]` | every committed probe, the base model's probe answers, the training history, a selection evaluation | `probes`, `groups`, `history`, `eval` |
| `python -m evotaste.analysis.washout runs/<name> [--selection <dir>]` | the per-response context scores, probe answers | `index`, `specific`, `hits`, `identification`, `themes`, `noise`, `jargon` |
| `python -m evotaste.analysis.divergence runs/<name> --tag T [--null-tag T0] [--step S \| --members a@60,b@60] [--classifier-items 400]` | an evaluation with two or more samples per item | `interaction`, `distances`, `profile`, `traits`, `trait_spread`, `null`, `authorship`, `format`, `length` |
| `python -m evotaste.analysis.length runs/<name> --tag T [--null-tag T0] [--step S \| --members ...] [--boot 1000] [--perms 1000] [--classifier-items 400]` | the same evaluation | `members`, `interaction`, `bands`, `association`, `pairs`, `authorship`, `null` |
| `python -m evotaste.analysis.harvest runs/<name> --tag T [--step S] [--splits 500]` | an evaluation | `splits`, `summary`, `best_of_n`, `reliability` |
| `python -m evotaste.analysis.heritability runs/<name> --tag T[,T2] [--null-tag T0] [--selection <dir>]` | an evaluation, and the context scores for the specific index | `families`, `icc`, `regression`, `distance`, `pairs` |
| `python -m evotaste.analysis.seeding runs/<name> [--selection <dir>]` | step-0 probes, the seeding history, the context scores | `members`, `domains`, `kl`, `accuracy` |

| `python -m evotaste.analysis.distinct runs/<name> --step S [--selection <dir>] [--boot 1000] [--perms 5000] [--classifier-items 150]` | a cross-likelihood table of `evaluate deviation --cross`, probe answers | `margins`, `distance`, `members`, `identification`, `claims`, `coherence`, `clones`, `length`, `authorship` |
| `python -m evotaste.analysis.arms runs/<name> [--census <c>] [--deviation <dir>] [--partial] [--boot 1000] [--classifier-items 150]` | probes, training history, a deviation table | `history`, `fields`, `probes`, `pairs`, `deviation`, `practice`, `practice_common`, `authorship` |

| `python -m evotaste.analysis.validate [--reps 200] [--studies pilot,length,likelihood]` | nothing: simulated members | in `results/validation/` |
| `python -m pytest tests/test_analysis_stats.py tests/test_analysis_runs.py` | | about a minute each |

Every command limits BLAS to 8 threads, since the host's CPUs are shared; the newer commands take the number of bootstrap draws (`--boot`, default 1000) and of relabellings as options so that a run fits beside the experiments (each finishes in minutes; the text classifiers take most of it). The context scores are the per-response file `responses.csv` of the run's only selection under `runs/<name>/context_score/` unless `--selection` names one; its sums must reproduce the selection's `table.csv`. A run in progress is read as far as it is committed: without context scores, washout stops with a message and seeding reports accuracy only; without the evaluation, divergence and heritability stop with a message. The pilot evaluation should include `base` and, for the real-data null, have four samples per item, or come with a `--null-tag` evaluation that has four (for example `--adapters base --samples 4` on the same items). Divergence, the length decomposition and the harvest simulation take the members evaluated at one step (by default the step with the most labels). Heritability accepts several tags of the same items and samples, merged, so that the parents at the clone point and the clones at the end can come from separate evaluations. The headline numbers of divergence, the length decomposition, heritability and the harvest simulation read the dataset units only; the procedural format probe, which tests notation as much as content, enters divergence's format table and heritability as one trait (`format_probe`, its strict accuracy).

## What is read

- **Committed records only**: probe files up to a lineage's checkpoint step, amplification history below it, seeding history once the lineage has a checkpoint. Lineages that are pending or new contribute nothing; a worker stopped before its first checkpoint after step 0 (toy-d2) has no committed update.
- **Members**: from the frozen config, every lineage's context, level (placebo, stance, tactic, reference for the Round 1 habit, unseeded), theme, seeding variant (`opcd`, `opcd[math]`, `imitation`, `none`), update rule, parent, root (the seeded member a chain of clones continues), and the strength of its taste-shaped reward if it sets one. The update rule names every term the engine computes: the advantage (`centered`, `standardized`), then `+si<β>`, `+ex<γ>x<weight>` (exaggeration), `~free` when the imitation terms take only successes within the free length, `+pr<η>` (practice; `+prb<η>` relative to the base model's pass rate) and `+taste<strength>`; a term the engine skips (weight, γ, η or strength 0) is not named, so equal names mean equal updates (pilot D: `centered`, `centered+ex1x0.01~free`, `centered+pr4`; pilot E's neutral clones have their parents' rule). The washout's controls are the placebo and unseeded members. A clone's first probe is a second sample of the checkpoint it copied: it enters the noise estimate of the washout and nothing else, so that no state is counted twice.
- **Labels**: `base`, `<lineage>` (its last checkpoint) and `<lineage>@<step>`. Labels whose adapters have the same content hash are one model (a clone at its clone point is its parent's checkpoint, a step-0 twin its parent's step 0); one label is kept, the original lineage's before a clone's, and the report lists the others. Evaluation samples are seeded by adapter content and item, so such labels would otherwise enter as two members with identical answers.
- **Units**: near (held-out items of a training source), far (an unseen unit) and procedural (the reasoning-gym format probe), from the frozen suites file. Accuracies are means over items. The engine's probe accuracy is a mean over units, but the probe set has one instance of each procedural family, so that mean gives each single draw of a family the weight of a source's dozen items (on pilot B's math probes it put one seeded member 8 points above the reference where the item mean put it 1 point above).
- **Strata** of selection items come from the census's selection part (`--census`): the base model's four samples, frontier when none is correct, mastered when all are, sweet otherwise. They are independent of the evaluated samples, so comparing members with the base model on base-frontier items has no regression to the mean. Without `--census` the stratum rows are absent and the report says so.
- **The reference** for accuracy and the other health metrics is the mean of every probe (or evaluated label) of the base model's weights: its prepare-time answers and the step-0 probes of unseeded members and of their clones (an unseeded adapter starts with B = 0). Pilot B has two such draws, pilot C seven. A difference is member minus reference on the same items; its interval resamples items on both sides and so carries the noise of both. The seeding command also averages a member's own draws: its step-0 probe and its clones' first probes.
- **Likelihood tables**: a deviation selection `runs/<name>/deviation/<N>items-<hash>/` (the run's only one, or `--selection`; its items are the context score's for the same `--items`): `responses.csv`, the summed log p_author − log p_base of every author's answer to every item, and `cross-<step>.csv`, every scorer's summed log-probability of every author's answer. The engine writes `responses.csv` only when the command finishes; `--partial` reads a selection still being scored from its per-author cache files instead, each kept only if its SHA-256 of the answers file matches the author's current committed probe (a checkpoint and its probe are committed together, so new answers come with a new file; the adapter's hash, which the engine also checks, is not recomputed). Authors are committed member probes `<lineage>@<step>` and finished scaled probes `<lineage>@<step>x<factor>` (`runs/<name>/scaled/<label>/`, read once `probe_summary.json` exists).
- **Format guards**: the per-family accuracy recomputed from the records must equal the engine's probe and evaluation summaries; every subject must answer the same items (uid, family, domain, kind, wrapper, question) with every sample exactly once; every subject of a context-score selection must have every context and item once, with the same tokens under every context, and the sums must reproduce `table.csv`; every author of a deviation table must have every item of `selection.json` once, in the base model's domains, and every scorer of a cross table every author's answer to every item once with the same tokens. Any mismatch stops the command. `tests/test_analysis_runs.py` runs every command on a run written by the engine's own code with the stand-ins of `tests/engine_fakes.py`, scaled probe, deviation and cross-likelihood tables included, so a change of the record formats breaks a test.

## Estimators

### Cells and the noise correction

Data are cells: Y[m, i], member m's mean over its samples of item i, and V[m, i] = s²/n, the unbiased estimate of that mean's sampling variance (for K Bernoulli draws Y(1 − Y)/(K − 1)). Every variance, distance and interaction below is a quadratic form in Y; its plug-in value carries the noise Σ (diagonal weight) × Var(Y) on top of the truth, and subtracting the same sum with V makes it exactly unbiased, whatever the solve probabilities. For one cell this is the U-statistic of its samples, which equals the spec's cross-half product averaged over every assignment of the samples to two halves; it is the minimum-variance unbiased estimator given the cell counts, so it is used in place of a single split (a test checks the identity exactly on a small case). It needs two samples per item; with one, divergence refuses and heritability leaves distances out. Negative estimates are kept in the tables; an SD is reported as √max(0, ·).

### Member-by-item interaction

The plain estimator is the spec's: the mean square of Y[m,i] − Y[m,·] − Y[·,i] + Y[·,·] on (M − 1)(N − 1) degrees of freedom minus its noise, that is MS_interaction minus the mean of V. It is reported on all items, on items that are neither never nor always solved (pooled over members and samples), and within each domain, for all members, per update rule, and as the difference between rules with paired draws.

On the probability scale, members that differ only in overall level show an interaction: one that is uniformly better in logits gains most on items of middling difficulty. In simulation this alone makes the plain SD about 0.85 times the members' accuracy SD (an accuracy SD of 3 points gives a plain interaction SD of 2.6 points), which is the size the pilot can detect. The **adjusted** estimator, the one to read, removes it: items that are neither never nor always solved are split into 10 classes of nearly equal size by their pooled solve rate (items of equal rate together), and the interaction is measured within classes, with each member's effect per class removed, on Σ (M − 1)(N_c − 1) degrees of freedom. Under identical members an item's class depends on its data only through its total, given which the samples are exchangeable, so the estimator stays exactly unbiased; with real differences it runs a few percent low because the classes see the data (see Validation).

The **residual interaction** generalises both: each item's column of solve rates is cleared not only of its mean over members but of its linear dependence on member covariates z (members × k, for example the update rule and log mean length), with the projection P = I − H of the hat matrix H of [1, z] in place of the centring, on (M − 1 − k)(N_c − 1) degrees of freedom. A cell's noise term is its V times P's diagonal entry, so the estimator is exactly unbiased for the same projection of the true solve probabilities whatever they are, provided z does not depend on the samples (a test checks the cross-half identity exactly). Every item gets its own slope on each covariate: this is the "sensitivity to length" of the length decomposition below.

### Functional distance, profiles and traits

The distance of members a and b is the mean square of δ_i = Y[a,i] − Y[b,i] after removing its mean, on N − 1 degrees of freedom, minus its noise (plain, the spec's); the adjusted distance removes the mean within each difficulty class of the evaluation. The domain and source profiles are the member-by-group interaction of group accuracies beyond noise, on (M − 1)(G − 1) degrees of freedom. For every counted and layout trait, the between-member variance of member means beyond their noise is the sample variance minus the mean noise variance; a cell with a single value takes its member's mean within-cell variance.

Counted traits: share of open answers given by program (the `program` channel), response length, lines of explicit checking (lines with check, verify, confirm, plug, substitute back, validate, satisfy or sanity), and over the syntax tree of a code answer's program: non-comment lines, loops, comprehensions, recursion, imports, helper functions. Layout traits, kept apart: bold spans and LaTeX markup per 100 characters, shares of header and list lines, words per line, horizontal rules. Length is also reported per member and domain (`length.csv`): mean and 90th percentile of completion tokens and the share truncated, which heritability uses as scalar traits. `format.csv` gives, per member on the dataset units and on the format probe, strict accuracy, `correct_any`, compliance and the gap `correct_any` − strict.

### Bootstrap

Intervals are 95% percentile intervals of 2,000 draws in which items are resampled with replacement within each unit kind (near, far, procedural) of each domain, the same draws for every subject, so differences between members, rules, or a member and the base model are paired. In a draw, an item drawn twice is two items whose samples are the same draws, so the noise terms weight it by w² where a mean over items is squared. Counting the copies as independent instead biases every replicate downward by about (number of classes) × (mean cell noise variance) / items, half a bootstrap SD for the adjusted interaction at the pilot sizes, and the intervals undercover (91% instead of 94% in 80 simulated evaluations). Interaction and distance intervals are conditional on the evaluated members; they do not cover what other seeds would have done.

The real-data null takes every adapter of an evaluation with four or more samples and splits its samples into halves: two copies of one adapter, whose distance is zero. `null.csv` reports each and their mean; an interval that excludes zero would mean the correction fails on real data (correlated samples, for example).

### Heritability

A family is a root lineage's members under one update rule: the seeded member and every clone descending from it, chains included (nested clone points are not distinguished). Unrelated pairs are members of different roots under the same rule at the same step. At every step where some family has two evaluated labels:

- the ICC of each scalar trait (accuracy, by domain, every trait above, and the specific context index when scored) over the families with two or more members, one-way with the rule as a fixed effect when rules are pooled;
- the regression of the family mean on the parent's value at the clone point, when three families have their parent's `<parent>@<clone step>` evaluated under the tag;
- the mean distance of clone pairs and of unrelated pairs, their difference and ratio, beside the null's mean distance.

Intervals resample families within each rule together with the items; pairs between two copies of one family are left out. p-values relabel members across family slots within each rule (5,000 relabellings; `relabellings` is the number of distinct partitions, which bounds the p-value's resolution). Labels at several steps in one evaluation show how the distances grow from the clone point to the end.

### Washout

For subject x, context j and domain (and over all domains, token-weighted), S_j(x) is the mean log-ratio per token of the context-score table and I_j(x) = (S_j(x) − S_j(base)) / (S_j(base under j) − S_j(base)): 0 for the base model, 1 for its answers under j. Where the denominator is not positive the index is undefined and listed. All contexts are those of the table's selection. The specific index of a seeded member with context c is raw = I_c − mean_{j≠c} I_j minus the mean of the same expression for the controls at the same step under the same rule; its ratio to the root lineage's value at step 0 is the retention. Identification asks whether c ranks first among the scored contexts other than the placebo after subtracting the controls' mean index per context; when each candidate is the context of one member, chance is exactly one over the number of candidates (exact binomial test, Clopper–Pearson interval). Stances and tactics are paired by theme at each step, rule, seeding variant and domain, with a bootstrap over themes and the exact sign-flip p-value. The sampling noise of one value comes from probes of one checkpoint by a parent and its clones at the clone point (step-0 twins included): SD = √(mean squared difference / 2), for the index and for the raw contrast. Intervals resample the selection's items (stratified as above), the same draws for every subject and reference. The specific index factors exactly into two parts in nats per token: specific = gain / effect, with effect = S_c(base under c) − S_c(base), how far the context moves the teacher's answers, and gain = specific × effect, the member's own-context gain S_c(member) − S_c(base) after the same two contrasts (the controls at that step and rule, and the drift on the other contexts converted to the own context's scale). A large index on a small effect and a small index on a large one are thus told apart: on pilot B the stances absorb 0.25–0.34 of effects of 0.03–0.06 nats (gains 0.010–0.015), the tactics 0.08–0.21 of effects of 0.09–0.31 nats (gains up to 0.053). `specific.csv` also holds the plain gain S_c(member) − S_c(base). Stance − tactic differences carry an interval over items (the measurement) and one over themes (generalisation). Between update rules, each seeded state trained from step 0 under both rules gives a paired difference of specific indices (`rules.csv`), averaged by level with an item interval and the sign-flip p-value over states. The noise of one value is reported per step of the shared checkpoint (`noise.csv`); the ratio to step 0 is printed only when the step-0 index is clearly above zero. The jargon share is the share of probe answers containing a term of the contexts file's list (case-insensitive substring).

### Health and seeding

Per probe and per evaluated adapter: accuracy, by domain, near, far and procedural units, by stratum (item means), compliance and accuracy under held-out wrappers (`HELDOUT_WRAPPERS` of the verifier), compliance under the default wrapper, format loss (mean `correct_any` minus mean `reward`), share truncated, length mean and percentiles, share of open answers by program and accuracy per channel. Accuracy, near, far, mastered, frontier, held-out compliance, format loss and truncation carry the difference from the reference with a paired interval; `groups.csv` averages these differences over members per probe step, rule and seed level, leaving out reference draws and clones' first probes. `history.csv` holds every committed update (reward, return, informative groups, length; the KL of seeding). `training_length.csv` averages the training rollouts per rule and step (tokens, share truncated, reward, and the return's length deduction reward − return); `probe_length.csv` gives per rule and probe step the mean and 90th-percentile tokens, the share truncated and the accuracy lost to truncation, the truncated share weighted by the reference's solve rate on those items (a truncated answer scores 0, and almost none holds a final answer, so `correct_any` cannot measure the loss). The seeding command reports, for every seeded member that is not a clone, its KL from first to last update, the specific index with gain and effect overall and by domain at step 0, whether its own context ranks first (and which ranks first otherwise), its jargon share, and its step-0 accuracy by domain against the reference, with the number of draws on each side.

### Harvest simulation

Inside the selection suite, on its dataset units, the members evaluated at one step are ranked on a select half and scored on the test half, 500 times per mode: halves of whole units within each domain (selecting on some sources, testing on others), and halves of the items within each unit (the same sources, an upper bound). Per split: the lead over the population mean of the top 1 and the top 3 on both halves, the retained fraction (test lead / select lead, median over splits), the Spearman correlation of members' scores between halves, and the expected test lead of the best of n random members for n = 1, 2, 4, 8, 14 and 28 (exact: the member of select rank r is the best of a random n-subset with probability C(M − r, n − 1) / C(M, n)). Intervals cover the splits with the items fixed, and the splits with an item bootstrap draw each; all members and each rule. `reliability.csv` gives the between-member variance of accuracy beyond sampling noise and its share of the observed variance. A simulated test checks that a real level difference is retained and that identical members retain nothing. What it cannot show: the vault's unseen units are the other half of each domain's units, and its held-out items of training sources are new; nobody has looked at either. The retained fraction is an optimistic bound for the vault, the item split more so, and the simulation takes the evaluated members as the population.

### Authorship

Units are alternately assigned to two halves in sorted order; a classifier trained on sample 0 of up to `--classifier-items` items of one half predicts the member on the other half, both ways. It reads one view of a response at a time: the text with digits replaced (raw), the text stripped of layout and notation (LaTeX, math delimiters, markdown emphasis, headers, list markers, rules, line structure and case), the layout traits alone, the first 600 characters of the raw or of the stripped text (prefix, stripped prefix: views that hide how long the answer is), or the answer's log length and whether it was cut off (TF-IDF word and character n-grams, or the standardised features, with logistic regression). Accuracy is pooled over both directions with a bootstrap over test items; a share contrasts two views on the same draws, (a − b) / (a − chance): the cosmetic share is raw against stripped, the length-cue share raw against prefix, the presentation share prefix against stripped prefix. Divergence reads raw, stripped and layout; the length decomposition raw, prefix, stripped prefix and length; distinct and arms raw, stripped and layout on probe answers.

### Length and truncation

The length command asks how much of the member-by-item interaction, of the pairwise functional distance and of the members' distinguishability is answer length. A member's length is its mean completion tokens (log) and its truncation the share of its samples cut off at the token limit, over all items of the scope (the dataset units, or one domain, whose covariates are then that domain's).

- **Residual interaction** (`interaction.csv`) for nested member models: none (the interaction itself), the update rule, + length, + truncation (left out when no member was cut off), each plain and adjusted, on all items, on the items on which no sample of any member was cut off ("clean"), on the others ("cut"), and within each domain. The share explained is 1 − residual / interaction; the length part is what length and truncation remove beyond the rule, as a share of the interaction, tested by permuting members' length and truncation within rules (the residual of the rule model is fixed, so the null is the part a covariate unrelated to the items removes, about zero). Because the mean pairwise distance is twice the interaction variance, the length part of the interaction is also the length part of the mean distance.
- **Members of similar length** (`bands.csv`): within each rule of six or more members, members sorted by length are cut into bands of about five; the adjusted interaction pooled over bands (sums of squares beyond noise over degrees of freedom) is set against the same statistic for random bands of the same sizes within rules: their ratio, with an interval over items whose denominator is the mean over 50 fixed random partitions, and a one-sided permutation p-value. This needs no linear model of length.
- **Distance against length difference** (`association.csv`): the adjusted pairwise distance regressed on the pair's |Δ log length| and |Δ truncation| with same-rule as covariate; partial correlations, the R² gain of both, and the joint slopes, with intervals over items (distances redrawn, covariates fixed) and one-sided p-values from relabelling members within rules (a Mantel test, which respects that pairs share members; not computed with fewer than 20 relabellings).
- **Distinguishability** (`authorship.csv`): the classifier on raw text, on its first 600 characters, on those stripped, and on length alone; the length-cue share is what hiding the length costs.

Truncation enters three ways: as a covariate, through the clean items (where it cannot act; this changes the items, so it is not a pure removal of truncation), and through the length-only classifier. Cut-off samples are not dropped from cells, because a cell with a single sample has no unbiased noise term.

### Deviation

From a deviation table: an author's deviation is Σ_i (log p_author − log p_base)(y_i) / Σ_i tokens(y_i) over its answers to the selection's items, an estimate of the per-token divergence KL(author ‖ base) on its own answers, exactly zero for the base weights (an unseeded member at step 0). It is reported overall and by domain, and per update rule and step as the mean over member probes (draws of the base weights, scaled probes and clones' first probes left out, as in health). Against length: the base model's typical length on an item is the median completion tokens over its probes of the base weights; the report gives the share of an author's answers longer than that, the deviation of the answers within it and beyond it, the deviation of an answer of exactly that length (the item-weighted least-squares line of an answer's per-token deviation on log2(tokens / typical), with its slope per doubling), and the Spearman correlation of an answer's per-token deviation with its relative length. Intervals resample items within unit kinds and domains, the same draws for every author.

On trained members the within/beyond split is nearly empty on one side: after 45 steps of pilot C 87–99% of a member's answers are longer than the base model's median on the same item, so "within" rests on a handful of selected answers. The deviation at typical length is then an extrapolation along the fitted line; it says whether deviation is carried by the length itself (deviation at typical length near zero, positive slope) or present at any length (the intercept), not what a shorter answer by the same member would look like.

### Distinctness by likelihood

From a cross-likelihood table at one step: the margin of author a over scorer b is Σ_i (log p_a − log p_b)(y_ai) / Σ_i tokens(y_ai), an estimate of KL(a ‖ b) per token on a's own answers, zero when b has a's weights; with b the base model it is a's deviation (the command checks this against the deviation table in the tests). The distance of two members is the mean of their two margins, distinctness the mean margin of a member over the others. Identification takes the member scorer that gives an answer the highest likelihood as its author, ties sharing the credit (identical scorers give exactly chance), overall and by domain; nothing is fitted, so every domain's rate is out of sample. A calibrated variant, which first lowered each scorer's likelihood by its mean margin over the base model on the others' answers fitted on the other domains, was dropped: it penalises a member for its own deviation and lowered a perfect identification on toy-d to 85%. Coherence is whether members are distinct in the same way on different domains: the correlation over member pairs of the distances measured on each pair of domains, with a Mantel p-value. The distance is set against the pair's difference in log length and in the share of answers at the token limit as in the length command. Clone pairs (heritability's families) against unrelated members of the same rule: mean distances, difference and ratio with intervals over items, and the permutation p-value over family labels. The authorship classifier on the same members' probe answers is reported beside it, raw and stripped, as the presentation check.

### Arms

For a run whose members train with different mechanisms. With taste-shaped members (pilot E, appended to pilot C) the arms are those members only, own (strength > 0), neu (0) and rev (< 0); otherwise every lineage that trains, grouped by update rule. Per arm and step: the training history (mean, minimum and maximum over members of reward, completion tokens, truncated share, informative groups, each term's rollouts, tokens and loss, and every history field whose name holds "taste", nested dictionaries flattened; `fields.csv` lists the expected fields that are absent); per probe step the mean over members of (member − reference) of health's metrics with intervals over items; the deviation and the deviation at typical length. For taste arms every comparison is paired by parent: own − neu and rev − neu averaged over the parents, for health's metrics and the deviation, with intervals over items and the per-parent values; at the clone step the three clones' probes are draws of one checkpoint, so that row is a null. Practice: each practising member's source shares per step, and the share of the members' movement of log shares (from the defaults, the shares of a step-0 history line, where every average is equal) carried by the mean movement, M Σ_s c_s² / Σ x², against 1/M, its expectation when members move independently. Authorship: the classifier among each arm's members, and among all trained members, per probe step, raw and stripped; at step 0 of unseeded members it is a null (draws of the base weights).

### Scaled probes

For every scaled adapter: factor 0 is health's reference (the probes of the base weights), factor 1 the lineage's own probe at that step, whose sampling seeds the scaled probes share, so differences from factor 1 are paired; accuracy, default and held-out compliance, format loss, truncated share, tokens and the deviation (from a deviation selection that holds the source and its scaled probes; the deviation of a scaled probe is scored with the scaled adapter itself), with intervals over items.

## Validation

`python -m evotaste.analysis.validate` simulates members with p[m, i] = logistic(θ_i + a_m + g_mi): θ_i ~ N(0, 3.2²), which reproduces the census's spread of base pass rates (39% of selection items never solved in four samples, 31% always), a level a_m and an interaction g_mi (SDs in logits); clones share part of both with their family. Each estimate is compared with the same quantity computed from p itself, and intervals are the commands' item bootstrap.

Interaction (two samples per item; 200 simulated evaluations at 14 members, 100 at 28; variances in pp², the mean bias with its standard error, and the coverage of the 95% interval):

The validation uses 500 bootstrap draws per evaluation, the commands 2,000.

The length decomposition (`--studies length`, 40 simulated evaluations per case at pilot C's size, 28 members × 1,840 items × 2 samples, 200 bootstrap draws and relabellings) adds lengths: a sample's log tokens are item + member + sample effects whose spread gives member means of 440–1,700 tokens, and a sample beyond 4,096 tokens is cut off and scores 0. In "length" an item's logit depends on the member's length with an item-specific slope (SD 1 logit per member SD) and the token limit applies, so all interaction comes from length; in "none" members differ as much in length but their interaction (SD 1 logit) is unrelated to it and nothing is cut off; "half" mixes both. The likelihood measures (`--studies likelihood`) are checked on members that are next-token distributions with an exactly known KL: at each of 20 positions of 80 items the base model's logits are N(0, 1) over 8 tokens and a member adds its own deviation; each member answers each item once and every one scores every answer exactly. With six members (40 simulations per case, 200 bootstrap draws), the margin between members is unbiased for the KL per token and its interval covers: identical members 0.0000 (truth 0), coverage 1.00, identification exactly chance 0.167; deviation SD 0.1: 0.0076 (0.0077), bias −0.00005 (0.00015), coverage 0.95, identification 0.26; SD 0.4: 0.1201 (0.1205), coverage 0.94, identification 0.63. ## Power at the planned sizes

For the planned pilot C (14 seeds under two rules, 2,000 to 4,000 selection items, two samples per item):

- **Interaction.** The adjusted interaction SD detectable at one-sided 5% with 80% power is 5.4 points with 14 members and 2,000 items, 3.9 with 28 and 3,000, 3.6 with 28 and 4,000 (plain: 4.6, 3.6, 3.2, but the plain estimator also reports level differences). 3.8 points is a logit SD of 0.25 per member and item. A member-by-item interaction smaller than that is not distinguishable from noise at these sizes; per rule (14 members each) the threshold is about the 14-member one.
- **Heritability of function.** With six parents of two clones each and half the interaction and level shared within a family, the permutation test of clone against unrelated distance rejected in 98% of simulations (14 parents: 100%). With three parents it cannot reject at 5%: three pairs have 15 distinct pairings, so the smallest p-value is 1/15.
- **Heritability of a scalar trait.** The ICC detectable at 5% with 80% power (normal theory, F test, two clones per parent) is 0.95 with three parents, 0.90 with four, 0.81 with six, 0.74 with eight and 0.60 with fourteen. In the simulation above (true accuracy ICC about 0.4) it was detected in 40% of runs with six parents and 46% with fourteen. With three parents the command's permutation p-value has the same floor of 1/15. Only a strongly heritable trait can be shown with the clone pairs the pilot can afford; a null result on accuracy is weak evidence.
- **Stance against tactic.** Five themes per rule give five paired differences. A paired test needs a mean difference of 1.66 SDs of the per-theme difference (0.99 with ten pairs, pooling the rules, which are not independent); the exact sign-flip test over five themes cannot reach two-sided 5% (its smallest p-value is 2/32) and reaches one-sided 1/32 only if all five agree. The noise of one raw contrast measured on the toy run is 0.006 index units (one clone pair, 357 probe items), so sampling noise alone contributes about 0.01 to the SD of a per-theme difference; how much the themes differ among themselves is unknown until pilot B.
- **Identification.** With eleven seeded contexts per rule and chance 1/11, at least 4 of 11 members must rank their own context first for p < 0.05.
- **Heritability by likelihood.** Pilot C's seven clone families that reach step 90 (three under the relative-only rule, four under self-imitation) give 1,575 distinct relabellings, so the smallest p-value is about 0.0006; in simulation (Validation) the test rejected in every run when clones shared half their deviation and kept its level when they shared none. Pilot E's taste arms have four parents, one clone per arm: a paired comparison over four parents cannot reach a two-sided sign-flip p below 1/8, so what can be read is the interval over items and whether all four parents agree.
- **Length.** At pilot C's size every test of the length decomposition rejected in every simulation where half the interaction came from length (Validation). On pilot C itself the length part of 9% lies above all 1,000 within-rule relabellings, whose mean is 0.5%: shares of a few percent are detectable.

## Limitations

- The washout's intervals cover the items of the context-score selection only (80 probe items on pilot B, 8 of them code), not the sampling of each member's answers beyond what those items carry; the clone-point noise measures the latter directly once clones are scored.
- The adjusted interaction and distance use classes formed from the data: exactly unbiased under identical members, a few percent low otherwise. The domain and source profiles are not adjusted for level, so a member better in logits everywhere shows some profile where domains differ in difficulty.
- Interaction and distance intervals are conditional on the evaluated members. With three to six families, intervals that resample families are not reliable; read the permutation p-value and the power section.
- The specific index and identification are defined over the contexts the selection scores. A selection of only the member's own context and the placebo, which the engine notes suggest for speed, reduces the raw contrast to I_c − I_placebo and leaves identification undefined (the command skips it); the washout as specified needs every context, on fewer items if need be.
- The engine writes a selection's `responses.csv` only when a context-score command finishes, so a selection still being scored cannot be read; its per-subject cache files hold the same rows, but they are the engine's internal format and are not read here.
- Probes are single samples: they serve means (health, washout, deviation, arms), never distances or interactions; the likelihood measures are distances between distributions, not between samples, so they need no second sample.
- Authorship reads a subsample, and its stripping is lexical. Its interval resamples test items with the fitted classifier fixed, so it leaves out the variance of the fit: among three draws of the base weights (toy-d2, step 0) it gave 35.8% [33.4, 38.2] against chance 33.3%. Read a small excess over chance among a few members as no evidence.
- The real-data null needs four samples per item, because two labels of one adapter give identical answers.
- The length decomposition is linear in log length and truncation share, one slope per item and covariate. In simulation, where all interaction came from length through the logistic link and the token limit, it removed about 95% (Validation); interaction that depends on length non-monotonically, or on a member's length on a particular item rather than its mean length, is left in the residual and read as "not length". The covariates are estimated from the same samples and treated as fixed (their noise, about 8 tokens against a between-member SD of 331 on pilot C, is ignored). Because each covariate also takes a degree of freedom per item, the length part is zero in expectation when length is unrelated to the interaction; the permutation null checks that on the real data.
- What the length decomposition attributes to length is association, not mechanism: a member that is verbose because it reasons differently, and solves different problems for that reason, counts as length. The residual is what length cannot explain; the length part is an upper bound on what verbosity itself causes.
- The clean items (no sample cut off) are a selection: shorter, easier problems, overrepresenting logic; a change of the interaction on them mixes truncation with item composition.
- Deviation is measured on the 80 (or 120) probe items of a deviation selection, one answer per item; its intervals cover the items, not a second draw of the answers. The base model's typical length is the median of seven (pilot C) or nine (pilot D) draws.
- The likelihood tables hold one sum per answer, so the share of deviation or distinctness that is presentation (layout and notation tokens) cannot be computed from them; the classifier's cosmetic share on the same answers stands in. A per-answer split of the sums into markup and content tokens would need the engine to write it.
- Identification by likelihood saturates: with answers of hundreds of tokens, a per-token margin of a few hundredths of a nat already identifies every author (toy-d: 100% of four members after five steps). The margins, not the rate, carry the information then.
- The clone test by likelihood has the resolution of its relabellings (seven parents, three under one rule and four under the other: 1,575 distinct pairings) and compares clones that share 45 steps with members that share none; that clones are closer is expected, the question is by how much and whether the ratio grows towards one.
- Practice's common share is computed against the defaults of the shared stream, read from a step-0 history line; a run whose practising members all start as clones after step 0 has no such line and gets no common share.
